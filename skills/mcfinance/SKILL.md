# McFinance · 门财报

把实际取得的个人订单整理成可核对的消费研报。用轻松的研报语气自嘲消费习惯与金融黑话，所有数字、偏好和判断都必须能回到数据。幽默不针对麦当劳品牌或产品，不鼓励浪费或为凑指标增加消费。

## 数据入口

- 有麦当劳 MCP 时，先发现当前工具和 input schema。官方 Server 为 `https://mcp.mcd.cn`，使用 Streamable HTTP 与 Bearer Token；让用户在客户端的本地密钥/环境变量配置中完成授权，不要求用户把 Token 发到聊天里。
- 主工具为 `order-list`，只读查询近期到店/外送订单。核对 schema 后再传参，不编造分页字段。分页、时间范围和历史覆盖有限时，在报告中写明已取得的样本，不声称全量。
- 没有 MCP 或认证失败时，使用用户已经提供的订单；也可在用户同意演示时使用明确标记的虚构数据。不能用示例响应冒充成功调用。
- 需要标准数据结构或字段映射时，阅读 [references/data-contract.md](references/data-contract.md)。缺少金额、时间或状态语义时，先确认数据或报告限制，不补造记录。

用户未说明时以最近 30 天为默认观察窗口、北京时间为默认日期口径。预算是用户自定参数；无预算时省略预算评级。保留实际查询时间、数据来源与观察窗口。

## 只读业务范围

订单分析只调用 `order-list`。用户明确要求券或积分补充时，可按当前 schema 只读调用 `query-my-coupons`、`available-coupons`、`query-my-account`；未返回的信息写“未查询”或“未知”。查询可领取券不代表已经领取；券面额不等于实际节省，积分不等同现金资产。

本技能不创建、支付、取消订单，不领取券、不兑换积分、不抽奖。额外业务操作不属于这份消费研报的执行步骤。

## 计算与输出

1. 统一金额单位、订单状态和日期；按订单标识去重，单独说明不计入的取消/全额退款/待支付记录。对未知状态、部分退款或异常金额保留限制，不能默认为正常消费。实际 API 的覆盖范围与字段语义优先于名称猜测。
2. 计算有效样本订单数、实付总额、平均客单价、按数量排名的常购商品、时间分布。原价未知时省略对应价差，不预测本可节省的金额；缺少可比上期数据时不写环比。
3. 若有预算，说明预算适用窗口，用本期实付/预算给出进度，不将消费更多写成更高成就。将数据与趣味解读分开表达，金句可用“本期第一重仓：{实际商品}，持仓 {实际数量} 份”等形式。
4. 生成简短研报，注明来源、日期、样本范围、KPI、两到三条有数据支持的观察，以及必要的数据缺口。无有效订单时输出空状态，不虚构偏好与评级。
5. 用户要求分享卡时生成本地 SVG，转义 XML 特殊字符，不嵌入外部脚本或私人原始订单。卡片仅显示汇总数字、真实可证的商品偏好和一句趣味解读；不放 Token、订单号、手机号、地址或账号标识。示例数据在卡上显著标注“示例数据”。需要时再导出 Markdown。

输出应清楚说明这是独立创意项目，非官方产品；金融话术只是消费复盘的表达形式，不构成投资或医疗/营养建议。无需长篇免责声明。

## 使用本仓库的可视化界面

若同时拿到了完整 McFinance 项目，可在项目根目录运行 `node server.js`，打开 `http://127.0.0.1:3210`，用示例、标准 JSON 导入或真实 MCP 同步生成报告。独立安装这份技能并不包含网页服务，也不依赖任何预设 CLI 脚本。根据当前客户端能力直接计算并生成所需文件即可。
